# Task R46-T019: Minimal Rule Explanation in Perl.gitignore

## Focus Patterns
- `.last_cover_stats`
- `/META.yml`
- `/META.json`

## Rule Narrowness, Anchoring, and Comparison Analysis

In Perl module distribution management (using `ExtUtils::MakeMaker`, `Module::Build`, or `Dist::Zilla`):
- `META.yml` and `META.json` are generated specification metadata files created at the repository root when generating a distribution.
- `.last_cover_stats` is created by `Devel::Cover` when running test suite coverage.

### Comparing Existing Rule `/META.yml` with Alternatives

| Rule Variant | Formulation | Result on Root `META.yml` | Result on Nested Test Fixture `t/fixtures/META.yml` | Evaluation |
|---|---|---|---|---|
| **Existing Rule** | `/META.yml` (anchored) | Ignored (Correct) | Visible (Correct) | **Optimal balance** |
| **Broader Alternative** | `META.yml` (unanchored) | Ignored | Ignored (**False Positive!**) | Erroneously ignores test fixtures |
| **Narrower Alternative** | `dist/META.yml` | Visible (**False Negative!**) | Visible | Fails to ignore generated root metadata |

- **False Positive demonstration**: If the broader rule `META.yml` (without leading slash) is used, any nested fixture file like `t/fixtures/META.yml` or `xt/data/META.yml` (which are part of the test suite and should be committed) gets accidentally ignored.
- **False Negative demonstration**: If a narrower rule such as `dist/META.yml` is used, the root-level distribution metadata `META.yml` generated by `perl Makefile.PL && make dist` remains untracked and leaks into `git status`.

The existing pattern `/META.yml` is precisely anchored to the root, preventing both false positives and false negatives.
