──────────────────────────────────────────────
1. PATTERN MECHANICS
──────────────────────────────────────────────

*/config/development:
  A glob with a leading directory wildcard. Matches a path whose second
  component is "config" and final component is "development" (e.g.
  application/config/development). The leading * means "any single
  directory component", so it only matches one level deep.

*/logs/log-*.php:
  A glob with a leading directory wildcard. Matches date-stamped CodeIgniter
  log files (e.g. log-2024-01-15.php) in any directory named "logs" one
  level deep. The * wildcard matches any string of non-separator characters.

!*/logs/index.html:
  A negation rule. Overrides any earlier ignore rule for paths that match
  "*/logs/index.html". The last matching rule wins in gitignore, so index.html
  inside any "logs" directory remains unignored and therefore tracked.

4. NEGATION BEHAVIOR NOTES
──────────────────────────────────────────────

git check-ignore -v --no-index reports exit 0 when the last matching rule
is a negation (e.g. !*/logs/index.html). This can be misleading. The file
is NOT effectively ignored. The authoritative check is git status --porcelain:
  - Output "?? <path>" means the file is untracked (not ignored).
  - No output (empty) means the file IS ignored.

This distinction was validated by manual testing before writing the check.

──────────────────────────────────────────────
5. LAST-MATCH ORDERING
──────────────────────────────────────────────

For application/logs/log-*.php, the CI3 rule application/logs/* (line 15)
is later than */logs/log-*.php (line 2). Git reports line 15 as responsible.
Both rules produce IGNORED; the later rule is the effective one.
